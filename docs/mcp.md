# Afflatus from outside (MCP)

Afflatus answers the [Model Context Protocol](https://modelcontextprotocol.io) at `/mcp`, on the same port as the app. An MCP client (Claude Code, Cursor, any agent that speaks Streamable HTTP) drives the whole studio through it: it sees where you are, reads and fills any form, renders, looks at the takes, edits timelines, files the library, edits the Prompt kit, finds and downloads models, changes settings, manages machines and rented GPUs. Each tool goes through the same code as the page, with the same checks and the same refusals, and each call is written to the token's activity. What it changes in the page you have open shows there at once, with Undo.

## Plugging it in

Make a token in **Settings › Access › Agents (MCP)**: name it after the client, tick its scopes, and copy it. It is shown once; Afflatus keeps only its SHA-256. The **Copy ▾** menu beside it gives the address and the Claude Code command, with the token filled in.

The server is Streamable HTTP, stateless: every call is a `POST /mcp` answered on its own in JSON, with `Authorization: Bearer afl_mcp_…`. It speaks protocol 2026-07-28 (each request carrying its own envelope) and the 2025 handshake (`initialize` first) alike. `GET` and `DELETE` answer 405, and a missing, wrong, revoked or ended token gets 401.

### Claude Code

Afflatus does not install Claude Code: the `claude` command comes with it (`npm install -g @anthropic-ai/claude-code`, or its own installer). Run the line below in a terminal outside your projects' folders, or with `--scope user`, so that it is not tied to one folder.

```sh
claude mcp add --transport http afflatus http://127.0.0.1:8721/mcp --header "Authorization: Bearer afl_mcp_…"
```

Add `--scope project` to keep it in a project's `.mcp.json` instead (it then holds the token: keep that file out of Git), or `--scope user` for every project.

### Any other client

Any client that speaks Streamable HTTP and sends a header: the address is `http(s)://<where Afflatus is>/mcp`, the header `Authorization: Bearer <token>`.

### Long calls

A client that takes MCP Tasks (the `io.modelcontextprotocol/tasks` extension of protocol 2026-07-28, which it declares in each request) gets a task rather than an answer from the calls that start long work: `render`, `render_clips`, `finish`, `export`, `run_workflow`, a slow motion of `cut_range`, and `deploy_pod` until the pod's ComfyUI answers. The client follows the task on its own (`tasks/get`, at the interval the task gives, from the queue's forecast) and hands the agent the result once the work has ended: the call's own answer, with each job's end as `job` says it (what it made, or why it failed), or whether the pod's ComfyUI answers. Nothing is sent while it runs: no progress, no calls from the agent. `tasks/cancel` cancels the task's jobs still waiting or running, as `cancel` does; a pod's task only stops being followed (the pod stays up until its idle stop, or `stop_pod`). The call is the same call: the same scopes, limits, spend caps and activity line; a refusal comes back as a refusal, at once. A task is its token's alone, survives a restart of Afflatus, and is forgotten a day after it was made. A client that does not declare the extension gets the answer as before, and follows the jobs with `job`: `job` with `wait` holds its answer until the job ends (at most 50 s a call, asked again while it runs).

**Claude Code** (2.1.304 or later) puts such a task in the background: the session stays free, and is woken once with the result (`/tasks` lists it meanwhile). Run through the Agent SDK (Sillage, scripts, `--input-format stream-json`), it declares Tasks only with this in `~/.claude/settings.json` (or the same variable in its environment):

```json
"env": { "CLAUDE_AUTO_BACKGROUND_TASKS": "1" }
```

Without it, a long render holds the session until it ends. A `claude` in a terminal should need nothing (its long calls go to the background by default; not tested here), and a one-shot `claude -p "…"` never gets Tasks. Tested with Claude Code 2.1.312 through the Agent SDK. Settings › Access shows, on each token's row, its client and whether it follows Tasks ("follows Tasks", or "Tasks off"), from its last call.

## Scopes and limits

Each token has its scopes, ticked one by one, and its own limits on top of the app's.

| Scope | What it gives |
|---|---|
| **Look** | Always on. Reads everything: where you are, the queue and machines, forms, drafts, the library, the kit, timelines, models, settings, costs; sees pictures, frames of videos and sounds. |
| **Make** | Forms and drafts, renders on your own machines, the queue (cancel, retry, pause and resume a machine, load a model), the library, the Prompt kit, timelines, workflows. |
| **Spend** | Rented GPUs: renders and model loads on a pod, deploying, starting and stopping pods, the GPU hunt, a pod's idle rule and watchdog, downloads onto a pod, unloading a pod's models, raising the app's caps. Moving waiting jobs onto a pod (Run on, Use only). While a pod is up, also what would move work onto it: pausing or removing one of your own machines, resuming the queue or a pod, changing what a machine takes, letting one of your jobs go to any machine. Off unless ticked. |
| **Manage** | Settings, downloads to this PC, model sets and model settings, changing and removing machines, lowering the caps. |

- **Renders an hour** (30 by default): every take, clip, cut, slow motion or model load it queues counts; past it, a render is refused until the hour has room.
- **Spend cap** (USD a month, $5 by default): what the token has spent on rented GPUs this month, counted as Costs counts it (each render or model load at its pod session's rate, with the idle time it left the pod until its next job or its idle stop), plus the whole run of any pod it deployed or started (boot and idle included). A render, a model load or a deploy that would pass it is refused, its waiting and running work counted; a deploy or a start also counts the next hour of the pods the token already runs. The refusal says the sum the cap was asked: what the token spent this month, what is committed (its work running and waiting, the pods it runs and their next hour) and what the call adds. A job already queued waits with `CAP_FULL` on its Queue row, with the same figures; a pod the token started is stopped once the cap is reached, or when its cap cannot be read, or once the token is gone. Moving waiting jobs onto a pod (`run_on`, `use_only`) counts them the same way, and a job of yours a token moves there becomes that token's: its Queue row names the token, and its time on the pod counts against that token's cap from then on. A GPU hunt a token starts is held to its cap and the app's caps for a pod at the hunt's ceiling, asked again when a GPU is found (a token that spent, lost Spend or was revoked meanwhile deploys nothing, and the hunt ends); the pod it deploys is that token's, counted whole. Changing that hunt in Afflatus makes it yours. A token without Spend never renders on a pod: its jobs stay on your own machines whatever the queue would pick. An ended token counts as revoked.
- **The app's caps** (Settings › Rented GPUs, a day and a month) hold over every token as over the page; a deploy or a start through MCP counts the next hour of every pod up against them.
- **A token with both Manage and Spend can raise the app's caps itself** (`change_setting rentCaps.*`): that is on purpose. Manage alone only lowers them. Its own spend cap is the one limit it cannot change; only you change it, in Afflatus. Give Manage and Spend together only to an agent you would hand your RunPod key.
- **An end**: never, 30 or 90 days. Making a token, changing its scopes, limits or end, and revoking it ask for the password past a sign-in of 10 minutes.
- **Workflows an agent imports wait for your Approve.** A workflow runs its nodes' code on your machines, and some nodes read or write files or fetch addresses (VideoHelperSuite's path loaders, WAS's file nodes). One imported through MCP shows in Studio › Workflows as "from <token>, waiting for you", with those nodes and what they are set to; nothing renders it until you click Approve once. Your own imports are unchanged.
- **Imports from an address** (`import_from_url`): one at a time per token, at most 1 GB each and 8 GB a token over 24 hours.
- **Uploads** (`upload`, a file's bytes as base64): one file coming in at a time per token (an import counts too), at most 16 MB each and 1 GB a token over 24 hours. A file goes through the web upload's own checks: read from its bytes, the real picture, video and sound containers only.
- **The activity**: under each token, every call in plain words (what it looked at, what it changed, what was refused and why), kept 30 days, and as CSV. Its last use says when, from which address and which client.

A token works on `/mcp` only: never on the API, never as a sign-in.

## Never through MCP

Whatever the scopes, these are refused with the reason, and stay in Afflatus itself:

- the password, tokens (MCP, metrics, a ComfyUI's), Lock and signing devices out;
- the Access settings, and where notices and reset codes go (Telegram, Discord);
- adding a machine, or changing a machine's address: every later render sends its prompts, pictures and cast faces there;
- secrets: API keys are said set or not, never read back nor written;
- Show in folder and the files' places on the disk; erasing for good (the bin is as far as an agent goes, and restore finds it there);
- Get ffmpeg, Afflatus's updates, ComfyUI restarts;
- accepting a model's licence;
- approving a workflow an agent imported or changed (the user's check of what it runs and reaches);
- installing a job's or a workflow's node packs (code on the machine, and a ComfyUI restart);
- deleting files of a network volume, or a volume (erased for good, no bin);
- deleting model files (Settings › Model files' Delete, Put back and Empty); `model_files` lists them with their use;
- forgetting the render times (the estimates and the caps are worked out from them);
- backups of the database;
- sharing an item (it goes out to the notify channels);
- linking or unlinking a folder of the disk (its path); Look again, a reading of one already linked, is offered.

## In the open page

What an agent changes shows in the page you have open, as it happens:

- **A form or a draft:** the fields change at once, what you are typing is kept, the changed fields are ringed in blue with the token's name until you edit them, and a toast says "<token> changed N fields" with **Undo**, which puts back only what still holds the token's value (a field you changed since stays, and the toast says so).
- **The Prompt kit:** the same, on the person, place, style or snippet open.
- **A timeline:** the editor follows with your selection and zoom kept, a clip form you are typing in takes the token's values (yours stay where you typed), the toast says the change with **Undo** (every step of that call, refused once the timeline changed after it), and the clips it touched are ringed until you select them.
- **The status bar** names the token behind a render: "Claude Code rendering 2 takes".

`whats_open` reads where the page is (the page, the draft, timeline or clip open, on the device used last), so an agent asked to "improve this" works on what you are looking at.

## From another device

`/mcp` is on the app's own address, so whatever reaches Afflatus reaches it.

- **On your network:** set `HOST=0.0.0.0` (and a password first: [SECURITY.md](../SECURITY.md)), and add the machine's name or LAN address to `ALLOWED_HOSTS` ([configuration](configuration.md)). The client points at `http://<that name>:8721/mcp`.
- **From outside:** put HTTPS in front with a reverse proxy (Caddy, nginx) or a tunnel (Tailscale serve, cloudflared), add its host name to `ALLOWED_HOSTS`, and point the client at `https://<that name>/mcp`. The proxy must pass the `Authorization` header through.
- **The token goes in the `Authorization` header, never in the address.** Afflatus does not read one from a query string, and an address with a token in it ends up in logs and histories.
- Pages of other sites are refused at `/mcp`, as everywhere in Afflatus.

### Forms

- `list_forms` · Look. Every form the user can use in Studio › Create, by model family: its id (what the other tools take), its title, what it makes (image, video, audio) and whether its files are ready on a machine. Families switched off in Settings › Models are named apart.

### Render and the queue

- `render` · Make. Render a draft as it stands (or a form with values): N takes, on a machine or wherever the queue would end it first. The same path as Create's Render, with the same refusals (an unfilled input, files that give black frames). The token's renders-an-hour limit holds; a rented pod needs Spend (a token without it never lands on one, picked or pinned) and stays within the token's spend cap, its waiting and running work counted. Answers the job ids (job, queue_status follow them) and what it may cost; a client that follows MCP Tasks gets that answer as a task, with each job's end, and has nothing to wait for (job's wait is for the others). Render a draft when the user should be able to open and change what made the take in Create (new_draft, edit_draft); a form with values leaves no draft. A video comes out on the model's own frame count, a little off the seconds asked (H3's 6 s: 5.875 s): not a failure.
- `queue_status` · Look. The queue now: what each machine renders (progress, time left, phase), the jobs waiting in order (when each starts, how long it takes, who queued it), whether it is paused, and when it is all done.
- `job` · Look. One job: waiting (when it starts, how long it takes), running (progress, time left, phase), or ended (done with the library items it made, which view_item shows; failed with why; cancelled). `wait` holds the answer until the job ends or that many seconds pass, rather than asking again and again: for a client that does not follow MCP Tasks (one that does gets the long calls answered as a task, and has nothing to wait for). A job not ended says when to check again (`hint`), from the queue's forecast.
- `cancel` · Make. Stop a job: waiting, it is taken out; running, its render is stopped on its machine. This token's own jobs and the ones the user queued; another token's are refused.
- `retry` · Make. A finished, failed or cancelled job queued again as it was sent (a new seed when its seed was random), optionally with some inputs changed (`values`). The same limits as render: renders an hour, and Spend for a rented pod.
- `pause_machine` · Make. Pause a machine (it ends what it renders and takes nothing new) or, with no machine, the whole queue. Nothing is lost: resume_machine goes on. Pausing a machine of the user's own while a rented pod takes work is refused unless that pod is one this token started (and then needs Spend): the user's work, and what they queue after, would go to the pod with no cap counting it.
- `resume_machine` · Make. Resume a paused machine or, with no machine, the whole queue. Resuming a rented pod that is up, or the whole queue while one is paused, is refused unless the pod is one this token started (and then needs Spend): the user's waiting work, and what they queue after, would go to the pod with no cap counting it. A machine of the user's own is resumed freely.
- `load_model` · Make. Load the models a draft (or a form with values) would render with, ahead of the render, as Create does while the prompt is written: a job in the queue that makes nothing. On a machine, or where its render would run. It counts as a render against the token's renders an hour; a rented pod needs Spend, and its load time (with the pod's idle time after it) counts against the token's spend cap.
- `order_queue` · Make. Put waiting jobs first, in this order, as dragging rows in Queue does: the jobs named go to the front in the order given, the others keep theirs behind them. A clip still waits for the clip it continues, wherever it is put. queue_status gives the ids.
- `run_on` · Make. Move a waiting job to a machine (pinned there, as Run on or dragging it onto a lane does), or with machine "any" back to whichever the queue picks. This token's jobs and the user's; another token's are refused. Onto a rented pod, or to "any" with the user's job while pods are up, it needs Spend and room in this token's spend cap with the job counted there; a job of the user's moved onto a pod becomes this token's (its spend, its Queue row).
- `use_only` · Make. Every other machine paused and this one going, as Queue's "Use only" does: everything waiting goes to it (a render under way elsewhere ends first). resume_machine undoes it. Onto a rented pod it pauses nothing: every waiting job that would go there (this token's and the user's, not pinned elsewhere) is pinned to the pod, as run_on does, and what the user queues afterwards goes where the queue picks. That needs Spend and room in this token's spend cap with those jobs counted; the user's among them become this token's (its spend, their Queue rows). Another token's jobs keep their own rules.
- `cancel_waiting` · Make. Cancel every waiting job at once, as Queue's "Cancel all waiting" does: this token's and the user's (with mine, this token's only); another token's are left. What runs goes on (cancel stops one).
- `unload_models` · Make. Unload the models now, as Queue's Unload does (the GPU's memory is wanted for something else): on a machine, or on every one that is not rendering. Refused where a render is under way. The next render loads what it needs again: on a rented pod that load is billed, so a pod needs Spend and room in this token's spend cap for one load there (the first render waiting for it, else the queue's floor), its work running and waiting counted; on a pod this token did not start it is refused while renders of the user's or another token's wait for it.

### Timelines

- `list_timelines` · Look. The timelines, the most recently changed first: id, name, how many clips and how long it plays, the clips left to render and the joins that no longer follow on, its project. `project`: one project's ("none" for the Inbox).
- `read_timeline` · Look. One timeline whole: its clips in order (each one's form and values, where it starts and how long it plays or is planned to, the take that plays and the other takes, its join with the clip before: cut or seamless, follows on or stale, its transition), its lanes (the recordings under Lip sync clips with the parts removed from them, the source video cut into windows, the music), what needs a look (clips to render, forms to fill, a continuation with nothing to carry on from, stale joins, failures, model set problems, clips of another shape), its planned and rendered length, what Undo and Redo would do, and its export. A clip's values are its form's, for its next render (seed -1: a new one each time); the seed a take was made with is that take's own (view_item › made with).
- `view_timeline` · Look. A timeline as a contact sheet you can see: one frame of each clip (the middle of what plays, labelled with its number), or with `joins` the last frame before each join and the first after it (labelled 2→3), with each join's facts (cut or seamless, follows on or stale, its transition). Clips with nothing rendered show no frame. Up to 24 clips at a time: `from` starts further on.
- `new_timeline` · Make. A new, empty timeline, in a project (or the Inbox) and optionally a folder its renders land in. Add clips with edit_timeline.
- `edit_timeline` · Make. Change a timeline as its editor does, one action or a short list run in order (each one a step of the timeline's own Undo; a refused action stops the list there, the ones before it done). Clips are named by id or by number (1 = first), as the timeline stands when the action runs. Actions (`do`): add (a form's clip to render, or a library video or picture); move; trim (what is seen, in the take's own time); split (refused on a recording's clip or a window of the source: remove it, or cut again); remove (the editor's ripple cut, asked nothing: the result says what went, undo brings it back; a recording's or the source's clip has its part cut out, bring_back puts a part from the middle back); bring_back; duplicate; join (cut, seamless, landing; or a transition on a cut, centred on it: it plays over the end of the clip before and the start of this one, and the timeline keeps its length); still (how long a picture is held); sound (a clip's own, muted, or a file); music (the music lane: song, volume, fades, ducking, where it plays from and the clip it starts with); recording (a voice recording made into Lip sync clips cut at its pauses, Clip length ± window); recut_recording; trim_recording; source (a long video on the Source lane: its stretch, windowed form, window length, scene cuts, the form's values such as the run-up); make_source; split_source; trim_source; settings (name, mood, frame, cast). Nothing renders here: render_clips does. An editor open on the timeline shows the change at once, with a toast whose Undo takes it back.
- `edit_clip` · Make. A clip's own form, as its panel in the editor changes it: any input by id (`set`, null to take it out so it follows the form's start again), checked as the form checks it (describe_form says each value), another form, its own cast (Prompt kit people), whether it is rendered to end where the next clip begins (landsOnNext). A clip of the source changes every window's form unless `share` says otherwise. One step of the timeline's Undo; an editor open on it shows the change at once, the clip ringed, with Undo.
- `render_clips` · Make. Render clips of a timeline through its Render: all that are left (no take, a stale join, another Mirror: Render all), a range of clip numbers, or the clips picked, in the order they play; a clip that carries on from one rendered with it waits for that one's take. The editor's refusals hold (a clip whose form is not filled; a continuation with nothing to carry on from, card #128; files known to give black frames), and the token's limits: renders an hour, rented pods only with Spend and within its cap. Answers the job ids (job follows them).
- `use_take` · Make. Make another of a clip's takes the one that plays (read_timeline › otherTakes), as clicking it in the editor's takes does. One step of Undo; the joins with its neighbours are said again by read_timeline.
- `finish` · Make. The Finish dialog: each clip's playing take brought to its final quality as a new take marked as the finish of its draft (which stays among the takes): SeedVR2, RTX VSR or a pixel model on the take's video, H3's latent re-sample of the draft's own kept latent, or a Face refine. Clips finished already are skipped unless `redo`; each skipped clip is said with why. The same limits as render_clips: renders an hour, rented pods only with Spend.
- `export` · Make. The timeline's Export: one video of it in the library, put together by ffmpeg (no model, no GPU). It waits in the queue behind the renders asked before it, its own clips' among them, as the editor's Export does; an export already on its way is answered rather than queued twice. read_timeline › export gives the item once it is done.
- `undo` · Make. The timeline's own Undo: its last change taken back (whoever made it, the user or an agent), with what it took back. Refused over a clip in the queue that the step would take away or change, as the editor's is. A take rendered since stays in the library and comes back with redo.
- `redo` · Make. The timeline's own Redo: what Undo last took back done again, until the next change.
- `timeline_range` · Make. What the editor's In and Out do to the range between them, on the timeline's clock (read_timeline gives each clip's atMs and lengthMs): split (the clips under In and Out each become two there); remove (what plays between them goes, the clips after close the gap; undo brings it back); regenerate (the range replaced by a new clip to render, pinned to the frame before In and the frame at Out, on a model that takes them; In = Out on a cut puts a clip between the two); loop (a new clip after Out that returns to the frame at In, so that the range plays round). Both answer a clip that is not rendered: render_clips renders it, edit_clip changes its form first. copy (that part of the timeline as one video in the library, through the export queue: ffmpeg, no GPU); slow (factor 2 or 4: the range made clips of their own, each slowed video arriving as a new take of its clip; RIFE on the GPU where ComfyUI has it, so it is held to the token's limits as a render is: renders an hour, rented pods only with Spend and within its cap). Each change is a step of the timeline's Undo; an editor open on it shows it at once, with Undo.
- `plan_clips` · Make. A scene written as several clips, as the designer's plan lays it: one new clip for each, at the end of the timeline, each carrying on from the one before, all in one form, each with its own texts (its prompt inputs by id → words: describe_form says which; you write them). Up to 12 at once. Nothing is rendered: render_clips does. One step of Undo for them all; an editor open on the timeline shows them at once, with Undo.
- `mask_preview` · Make. A Swap character clip's Show the mask, as its panel's: the window's tracking and masks alone drawn over its frames, as a short video kept out of the library (gone after a day); no take is made. A job on the GPU, held to the token's limits as a render is (renders an hour, rented pods only with Spend and within its cap), with the clip's form as its Render would send it. Answers the job; called again with `job`, where it stands and, once it is done, frames of the mask video to see.
- `remove_take` · Make. Remove one of a clip's takes, as its takes' Remove does: the video rendered for it goes to the bin with it, unless it was brought in from the library, something else still uses it, or it is a file of a linked folder (those stay where they are). The newest of the other takes plays instead when it was playing. Refused for the draft of a finished take (remove the finish first). undo brings the take back and its video out of the bin; restore brings the video back to the library alone.
- `bin_unused_takes` · Make. The timeline's unused takes go, their videos to the bin with them, as its Bin unused takes does: the takes no clip plays and nothing needs (not a draft a kept take was finished from or carries on from, nor a video another clip, timeline, person, preset or waiting job uses, nor a linked folder's file). Answers how many went and the space their videos take. One step: undo brings the takes back and their videos out of the bin; restore brings a video back to the library alone, until the user empties the bin.
- `duplicate_timeline` · Make. A copy of a timeline beside it (its project and folder), as its menu's Duplicate does: its clips with their forms, joins and transitions, their takes (the same videos of the library, playing in both), its music, source and recordings. Not its Undo history, its jobs or its last export. To try a change on the copy and keep the original as it is. Answers the copy's id and name.
- `delete_timeline` · Make. Delete a timeline, as its menu's Delete does: the sequence goes with its Undo history; the videos of its takes stay in the library. It does not come back (no bin, no undo): duplicate_timeline first to keep a copy. Refused while a clip of it is in the queue. `name` is the timeline's name as read_timeline gives it, to be sure of which one goes.

### Workflows

- `list_workflows` · Look. The ComfyUI workflows the user imported (Studio › Workflows), as that page lists them: each one's form id (workflow.<slug>, what run_workflow, describe_form, new_draft and render take), title, model, the file it came from, what it makes, how many nodes, whether a machine has what it needs, and its inputs by id. One that cannot be built any more says why (problem). One an agent imported that the user has not approved yet says so (waiting: the token's name, and its nodes that read or write a path or fetch an address); it renders once the user approves it in Afflatus. describe_form gives an input in full.
- `import_workflow` · Make. A ComfyUI workflow made into a form of Afflatus, as Studio › Workflows imports one: from its JSON (the file ComfyUI's editor saves, one saved with Export (API), or one shared from another Afflatus), from a public https address (a .json, or a picture or video ComfyUI saved with its workflow inside; at most 16 MB), or from a picture or video of the library that carries one. It is read against ComfyUI's node list, then kept with the mapping the import would start from (the prompt, seeds, size, length, pictures, LoRAs, switches and controls inspect suggests; a shared one keeps its own), unless `bindings` changes parts of it. Answers the new form's id (run_workflow and render take it), its inputs, the other settings that could be controls (addControls), and what is missing on this ComfyUI: node types and the packs they come from, model files (with where else they are, and where to get them when known), choices it lacks. Installing those stays in Afflatus. A workflow runs its nodes' code on the user's machines: import only what the user asked for. It waits for the user's approval (Studio › Workflows › Approve, in Afflatus) before it renders; the answer lists its nodes that read or write a path or fetch an address (reaches), which the user sees there too.
- `run_workflow` · Make. Render a saved workflow with values: the same as render with its form (workflow.<slug>), through Create's own path and refusals. One an agent imported renders only once the user approved it in Afflatus (list_workflows says waiting). Inputs by id (list_workflows, describe_form); the rest start as the form starts them. The token's renders-an-hour limit holds; a rented pod needs Spend (a token without it never lands on one) and stays within the token's spend cap. Answers the job ids (job, queue_status follow them) and what it may cost.
- `read_workflow` · Look. A saved workflow's mapping, as Studio › Workflows › Edit shows it: which node and input the prompt, negative, seeds, size, length, opening and ending pictures, LoRAs, switches (toggles), controls and result are, what is left out (skip), how the form is laid out (sections); with its nodes by id, each one's type and title, and what it reaches (its nodes that read or write a path or fetch an address). edit_workflow changes the mapping.
- `edit_workflow` · Make. Change a saved workflow's mapping (read_workflow gives it), as Studio › Workflows › Edit saves it: each key of `bindings` given replaces that part whole (prompt, negative, seeds, size, length, startImage, endImage, loras, toggles, controls, result, skip, sections), null leaves it out; its title and model too. Checked as the page checks it (every node and input named is in the workflow, ids unique) and built once before it is kept; its graph stays as it is. What a form sets is part of what a workflow reaches: once an agent changed it, it waits for the user's approval again (Studio › Workflows › Approve, in Afflatus) before it renders, even one the user imported. Approving stays the user's.
- `delete_workflow` · Make. Delete a saved workflow, as Studio › Workflows' Delete does: its form goes from Create. What was made with it stays in the library; drafts on it stay too, and say it is gone. It does not come back but by importing it again.

Needs Download missing models on in Settings › Models (a family's usual file excepted). A file under a preset's licence the user has not accepted is refused. Onto a pod needs Spend (a pod fetching is billed). Answers the download; downloads follows it.
- `downloads` · Look. The downloads line: each file being fetched, waiting its turn, done, failed or stopped, with its bytes, who fetches it and on which machine. change_downloads cancels, reorders, tries again or clears.
- `change_downloads` · Manage. Act on the downloads line as its card does: `cancel` a download under way or waiting (nothing is left behind), `move` a waiting one before another waiting one of the same machine (or to the end), `again` a failed or stopped one as it was first asked, `clear` the finished ones off the list.
- `model_sets` · Look. The Model sets (lists of model files to bring onto a machine or a pod at once: presets' files and files of their own), each with its presets, their licences and whether the user accepted them, how many files and their size. `set`: its files, each with where it comes from and which machines have it already.
- `edit_model_set` · Manage. Make, change, duplicate or delete a Model set, as Settings › Models › Model sets does; or `get` its files a machine lacks onto it (a ComfyUI of the user's own through the downloads line, a pod through what it fetches: that needs Spend). A preset under a licence the user has not accepted is refused: the user accepts it in Afflatus.
- `model_settings` · Look. The values saved with a model file (its sampler, steps, CFG, quality tags…: a family's inputs marked per model): the start whenever that file is picked in a form, a draft recording only what it changes on top. `family`, `file`: one family's or one file's.
- `change_model_settings` · Manage. Save the values that travel with a model file, as the form's Save for this model does: only the family's inputs marked per model are kept (describe_form says which: perModel), the rest dropped. `values` null (or empty) forgets them: the form's own start again.
- `model_files` · Look. Every model file in ComfyUI's model folders on this PC, as Settings › Model files lists it (in GB): its folder and kind, its name and base model where Civitai, Hugging Face or its header say them, how many Afflatus jobs loaded it and when last (renders made straight in ComfyUI are not seen: say "not used by Afflatus since", never "unused"), its takes, the presets and model sets that need it, its extra copies (same sha256 in another file on disk), and alsoSeenAs: the same file on disk seen through another folder (a folder extra_model_paths.yaml lists twice), which is not a copy. `machine`: another machine's files, names only, from its last scan. `notUsedDays`: only those no Afflatus job loaded for that long. Biggest first. Deleting model files cannot be done through MCP: the user does it in Settings › Model files.

### Machines and rented GPUs

- `list_machines` · Look. Every ComfyUI the queue sends work to (this PC's, another computer's, rented pods), asked now: whether it answers and why not, its ComfyUI version and PyTorch (and the families that version is too old for, with the version they need), GPU and Afflatus node pack, what it takes (everything, pictures or videos), paused or not, its families switched by hand; a pod's state on RunPod, price, this run's cost and idle rule.
- `edit_machine` · Manage. A machine's address, adding a machine, node packs installed without asking, open ports and its folder on this computer are the user's, in Afflatus itself.
- `remove_machine` · Manage. Take a machine out of Afflatus, as its card's Remove does: nothing more is sent there. Removing a machine of the user's own while a rented pod takes work is refused unless that pod is one this token started (and then needs Spend): its work would go to the pod with no cap counting it. A machine taken out is added again by the user, in Afflatus.
- `reconnect` · Make. Ask a ComfyUI (or every one) afresh what it has, as the queue's Reconnect does: a model or node pack put in by hand, a ComfyUI restarted, is seen now, and a job that waited for it may start. Answers whether each answers.
- `pods` · Look. The rented pods Afflatus follows: each one's state on RunPod, price, this run's cost, time left before its idle stop, idle rule, and the token that started its run. `gpus`: the GPUs deploy_pod may take now on that cloud, with their price an hour and whether they are free. `account`: every pod of the RunPod account, added or not (the user adds one in Afflatus).
- `deploy_pod` · Spend. Deploy a new pod on RunPod, as Settings › Rented GPUs › Deploy does: billed from now. The choices the dialog gives, the last deploy's when left out: the GPU (pods with gpus lists them with their price), Secure or Community cloud, Afflatus's image or RunPod's ComfyUI, a network volume, its disk, its idle minutes and what it does then (terminate by default here), its watchdog, a Model set whose files it fetches (a preset under a licence must have been accepted in Afflatus first). - `start_pod` · Spend. Start a stopped pod, as its card's Start does: billed from now. Refused when this token's cap or the app's caps have no room for its first hour at its last price (with the next hour of the pods already up), and for a pod whose idle stop or watchdog is set to never (edit_machine sets them); its run then counts against this token's cap, and it stops once that cap is reached (or at its idle stop).
- `stop_pod` · Spend. Stop a pod (its GPU stops billing; its disk goes on billing and it can be started again) or terminate it (deleted on RunPod with its container disk, nothing billed after, and gone from Afflatus; a network volume keeps what it holds). Refused while it renders something this token did not send: that render is the user's (or another token's) to stop.
- `costs` · Look. Queue › Costs: what the rented GPUs cost this month (RunPod's bill where read) and today, against the caps; the pace a day and the month's end at it; RunPod's balance and how long it lasts; where the pods' time went (rendering, idle, booting, fetching files); the costliest projects; the newest pod runs, each with its GPU, length, cost and why it ended; and advice. A window in ms (from, to), else everything.
- `caps` · Look. The rented GPUs' spending caps (a day, a month; 0: none) with what is spent against them, RunPod's balance, and this token's own cap and spend this month. At a cap the running render ends, then the pods stop, and a deploy or Start is refused. The app's caps are changed with change_setting (rentCaps.day, rentCaps.month: Manage to lower them, Spend too to raise or take them off); this token's own in Afflatus only.
- `hunt` · Look. Hunt a GPU, read: the hunt under way (none: null) with its state (hunting, deploying, up), its choices, who started it and what it found, and the GPUs as it last ranked them for the renders waiting (price, usable or why not, how free, the time and cost of a render there). With `rank`, the ranking for those choices now, as the Hunt dialog shows it as it is filled (RunPod read at most every 20 s), hunt or not.
- `start_hunt` · Spend. Start a GPU hunt, as Queue's Hunt a GPU does: RunPod's stock is asked every 30 s and the best-ranked usable GPU at or under the ceiling is deployed the moment one is free, once, while renders wait for it. hold rest pauses the user's own machines meanwhile (resumed when it ends), refused while a pod this token did not start takes work (the user's work would go to it, counted by nobody); keep lets them render on. Deploy choices as deploy_pod (the last deploy's when left out; idle 3 min then terminate here). Refused when this token's cap or the app's caps have no room for a pod's first hour at the ceiling; once found, its deploy is asked of the caps again, and refused it ends the hunt. The pod's whole run then counts against this token's cap, and it stops once that is reached. It gives up at its time, at a cap, or after three refused deploys.
- `change_hunt` · Spend. Change a hunt this token started: its mode, ceiling, GPUs left out, time (minutes from its start) or hold. A higher ceiling is asked of this token's cap and the app's caps as start_hunt asks it. A hunt the user or another token started is theirs to change.
- `cancel_hunt` · Spend. Cancel the GPU hunt: the machines it paused go on. This token's hunt or the user's; another token's is refused. Refused while its GPU is being deployed (the pod is billed from its first second: stop it with stop_pod once it is up). A pod it deployed already is a machine like any.

### Diagnostics

- `comfy_log` · Look. ComfyUI's terminal log on a machine, as the Queue page's log tab shows it: its last lines, newest last (a Traceback, a node that failed, a model that did not load, out of memory). A rented pod whose ComfyUI is not up yet gives its boot log instead (`source`). Secrets and folders on a disk are taken out: a key shows as [hidden], a path as its file's name. `since`: a line's stamp, for what came after it.
- `boot_log` · Look. A rented pod's boot (its image's pull, node packs, ComfyUI's start): `machine`, the boot log of a pod now, read from it; `run`, the boot log kept of a past run (Settings › Rented GPUs › Boot logs keeps them some days); neither, the runs whose boot log is kept, newest first. Secrets and folders on a disk are taken out.
- `job_live` · Look. A running job as the Queue page shows it while it renders: its phase, step and time left, the pictures its workflow showed on the way (its Preview nodes, as `stages`), and its latest live preview as a picture. `stage`: that stage's picture instead. Only while it runs: job says the rest.
- `render_stats` · Look. The Queue › Render times tab: over a period (day, week, month, all) or a window, the renders done, failed and cancelled, GPU time, loads, waits, each machine's renders and pace (1 the common pace, 2 half as fast) and each model's figures. `renders`: the renders themselves instead, newest first (each its model, machine, times and status), `trouble` for the failed and cancelled only. What a form will take is estimate's.
- `network_volumes` · Look. The RunPod account's network volumes (Settings › Rented GPUs): each one's size, data center, monthly price, the pod running on it now if any, and each Model set as the volume held it the last time a pod ran there (all there, or what it lacks). Read only: a volume is made, grown or deleted in Afflatus.
