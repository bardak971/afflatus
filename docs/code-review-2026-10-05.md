## HIGH

Real bugs a user will hit, or clear weaknesses.

1. **History filter by model or text finds nothing for most models** — `apps/server/src/queue.ts:977,980`. The `LIKE` patterns escape `%` and `_` with a backslash but no `ESCAPE '\'` clause is emitted; SQLite has no default escape character, so `\_` demands a literal backslash. Verified: `'sdxl_base' LIKE '%sdxl\_base%'` → 0, with `ESCAPE '\'` → 1. Nearly every model file name contains an underscore. Fix: `sql\`inputs like ${like} escape '\\'\`` (works on SQLite and Postgres) and a history test with an underscored name.
2. **No Host check: a web page can drive the local API by DNS rebinding** — `apps/server/src/app.ts:66` (and `fetchFile.ts:29` trusts `req.headers.host`). Any site open in a browser on the same machine can be rebound to `127.0.0.1:8720` and then read and write the whole API: link a folder, read any file, change an LLM base URL while the stored API key is kept and sent to it. Fix: an `onRequest` hook that rejects requests whose `Host` is not `localhost`, `127.0.0.1`, `[::1]`, the bound `HOST`, or `PUBLIC_URL`'s host.
3. **A backup over 4 GB fails at the end, silently** — `apps/server/src/zipStream.ts:54-56,75`, `backup.ts:93-98`. The zip has no zip64; once a file or the running offset passes 4 GiB, `writeUInt32LE` throws, the stream is aborted after the browser has already received gigabytes, the server logs nothing and the UI only ever showed the size. A video library passes 4 GB quickly. Fix: zip64 records, or refuse at `/api/backup.zip` when `bytes` or any file exceeds 4 GiB and say so in the plan; log the abort reason.
4. **A timeline's export state is read from the last 30 export jobs of every timeline** — `apps/server/src/timelines.ts:386-388`. After 30 exports elsewhere (copy-range jobs count too), `exporting` is null for this timeline, a second export can be queued on top of the first, and `exportFailed` is wrong. Fix: store the timeline id in a `jobs` column and index it.
5. **The progress bar overshoots on hires-fix, latent-upscale and LTX renders** — `packages/comfy/src/monitor.ts:303-310,214`. Every `progress` message is counted as sampler steps, but ComfyUI also emits `progress` from tiled VAE decodes and from `ImageUpscaleWithModel` tiles; after the first sampler those tiles are added to the step count, the bar pins at 0.99 and the ETA collapses. The fake ComfyUI only emits progress for samplers, so the tests cannot see it. Fix: ignore `progress` from nodes whose phase is not a sampling phase, and make the fake emit tile progress so a test pins the bar to the sampler total.
6. **"Latent: re-sampled" is silently skipped without the MMH3 upscale pack** — `packages/recipes/src/h3/video.ts:456,483`. The upscale pass is accepted by the form, then quietly dropped when `MMH3UltimateUpscale` is missing; the clip comes out at the original size, no error, no raw side file, though the form announced an enlarged frame. Fix: throw as the RTX route does, or list the `MMH3*` nodes in `nodes()` when the latent route is chosen so the queue refuses up front.
7. **Edits can be lost on a failed save** — `apps/web/src/draft.ts:32-40`, `apps/web/src/screens/People.tsx:545-552`, `apps/web/src/screens/TimelineEditor.tsx:106`. The pending edit is cleared before the request; on failure the status says "Could not save" (or nothing, in the timeline editor, where the error is swallowed and the local overlay keeps showing text the server never got) and nothing holds the edit for a retry. Fix: on failure put the draft back in `unsaved` and offer Retry; in the editor, surface the error and drop `edits[clipId]` only when the refetched clip carries the saved inputs.
8. **The unkeep countdown is not what the tooltips say** — `apps/server/src/sweep.ts:19-20`, `apps/web/src/screens/Library.tsx:20`, `Studio.tsx:772`, `Viewer.tsx:803,878`. "They go back on the one-day countdown" and "it goes to the bin after a day", but the sweep counts from `created_at`: an item kept for more than a day and then unkept, or an unkept item put back from the bin, is binned within the hour. Fix: a `countdown_from` stamp set on unkeep and restore, used by both the sweep and the "h left" label.
9. **Releases ship an unpinned, unverified runtime and ffmpeg** — `scripts/release/bundle.mjs:62-67,86`. Node is "the newest of major 24" from `nodejs.org/dist/index.json` (fetched without an `ok` check), ffmpeg is BtbN's rolling `releases/latest` master build; neither is pinned nor checksum-verified, and a cached partial archive in `release/` is reused as is. Fix: pin an exact Node version and a dated BtbN tag, verify `SHASUMS256.txt` and the release checksum, download to a temporary name and rename.

## MEDIUM

Performance, robustness and exposure.

### Server
- **Linking any readable directory** — `folders.ts:47-50` → `linked.ts:99-111`. Any client may link any path; everything under it is then served, written into and binned. Resolution is confined to the roots (good), but on a LAN or behind a proxy this is disk-wide read and write. Fix: an allow-list of linkable roots (`LINK_ROOTS`), refuse system directories, and say in the docs that LAN exposure needs it.
- **Crash window after a render lands** — `queue.ts:737-740`. `store()` inserts the generation and assets, then `clips.finished()`, then `finish()`; the job keeps `running` with `resume` set until the last step, so a crash between them resumes the prompt and stores it again (duplicate rows), or marks the job failed with its video already in the library and unkept. Fix: write `generation_id` on the job inside `store()` and guard against a second store; run `finished()` after `finish()`.
- **Backup hangs its producer when the client cancels** — `zipStream.ts:16-20` with `backup.ts:93`. `write()` waits for `drain`, which never comes once the reply is destroyed; the open read stream and the temporary copy of the database are never released. Fix: reject on `close`/`error` of the output, or use `stream.promises.pipeline` from an async generator.
- **Every video operation reads whole files into memory** — `cut.ts:30-37` and every caller: thumbnails, peek on hover, strips, motion, scenes, joins (three videos and ten ffmpeg runs per take), uploads to ComfyUI, and the export, which holds the bytes of every clip, still and the music at once (`timelines.ts:1669-1805`). Fix: give `Storage` a `localPath(key)` and have `cut.ts` take paths; exports then cost disk, not RAM.
- **Uploads are buffered and probed twice** — `app.ts:69,543-555`. Up to 512 MB in RAM, two temporary copies, two `ffprobe` runs. Fix: stream the body to one temporary file, probe once, move into storage.
- **Missing indexes** — `db.ts`. Only `assets(owner_id, created_at)`, `assets(folder_id)`, `jobs(status, priority, created_at)`, `clips(timeline_id, position)`, `takes(clip_id)` and a few history tables are indexed. Frequent lookups have none: `assets.generation_id` (every render completion and library filter), `takes.asset_id`, `jobs.clip_id` (every timeline view), `jobs.generation_id`, `jobs.depends_on`, both columns of `generation_inputs` (lineage on every viewer open, `NOT IN` in the sweep), and the library list's `ORDER BY created_at DESC, id DESC` cannot use `assets_by_time`. Fix: one migration with those indexes plus `assets(deleted_at, created_at, id)`.
- **`list()` runs three queries per timeline** — `timelines.ts:318-320`. Fix: one query each for clips, takes and covers across all listed timelines.
- **One load timer and eight listeners per browser tab** — `app.ts:385-393`, `services.ts:49-62`. Every SSE connection owns a two-second `setInterval` calling `comfy.load()`, and every `s.comfy()` call re-reads and re-parses the whole settings table; a second tab already trips `MaxListenersExceededWarning`. Fix: one shared timer broadcasting to all clients, settings cached until written, `events.setMaxListeners(0)`.
- **Search parses thousands of generations per keystroke** — `app.ts:440,462-464,503-507`; `/api/assets/models` parses every generation each time the filter opens; `/metrics` reads the whole `render_stats` table per scrape. Fix: cache `madeWith()` per generation (it never changes) and keep the model tally in memory, invalidated on `library` events.
- **Multi-table writes without a transaction** — `queue.ts:1106-1134` (generation row inserted before the first download; a failure leaves an orphan), `timelines.ts:1175-1198` (`cutRange`), `:642-654` (`addClip`), `linked.ts:121-127` (`unlink`), `queue.ts:283` (`reorder`). Only `restore()` is transactional today.
- **Derived files survive a linked file's change** — `linked.ts:193-195`: the rescan clears the thumbnail and measurements but not `strips/`, `motion/`, `scenes/` keys, so the track shows the old film strip; the in-process `joinScores` and `stretchMeans` maps grow without bound. Fix: delete the three keys there and in the sweep; cap the two maps.
- **Arbitrary outbound fetches** — `fetchFile.ts:51`, `downloads.ts:198`, `fromLink.ts:114`, `settings.ts:9,36`: download sources, `HEAD` on any resolved link, any `comfyUrl`, any LLM `baseUrl`. Reasonable for one user; an SSRF proxy once exposed. Fix: reject loopback, link-local and private targets for downloads and link resolution; validate `baseUrl` as a URL.
- **"Lookups off" is not "never contacts"** — `Setup.tsx:530` says Afflatus never contacts Hugging Face or Civitai with lookups off, but "Get a model from a link" and the download only check `downloadModels` (`app.ts:245-246`, `fetchFile.ts:34`). Fix: gate both on lookups too, or soften the wording.

### Web
- **The whole editor re-renders about fifteen times a second while playing** — `TimelineEditor.tsx:510-519,625`. `toggle` depends on `time`, which the player updates every 66 ms, so the keydown effect re-binds its listener on every tick and Track, Shelf, Inspector with its 661-line form and the Overview all re-render. Fix: read `timeRef.current` inside `toggle`; move `time` into a small transport component or a store.
- **Progress events refetch the whole queue** — `live.ts:40` with `app.ts:379-384`: up to four `GET /api/queue` per second during a render, and everything on `useQueue()` re-renders with each. Fix: carry the running job's progress in the event payload (as `system` does) and patch the query data; refetch only on `queue` events.
- **Library invalidation refetches every loaded page** — `data.ts:64-72`, `live.ts:41`: no `maxPages`, and `["assets"]` is invalidated on every `library` event and after each keep, bin or move; fifteen pages scrolled means fifteen requests per finished render. Fix: `maxPages` on `useAssets`, or `refetchType: "inactive"` for lists not on screen.
- **One advice request per slider pixel** — `RecipeForm.tsx:259-264` with `fields.tsx:393`. Fix: debounce the key as `ModelLoad.tsx` already does, or commit range inputs on pointer up.
- **Effects that re-subscribe on every render** — `RecipeForm.tsx:154,461-468` (`parts` is a new array each render; three listeners re-added per keystroke), `Track.tsx:250-300` (`useQueries` returns a fresh array; the motion smoothing reruns on every playhead tick), `Trim.tsx:124-128,164-187` (key handler re-bound per decoded frame), `MaskField.tsx:159-180,208-218` (two effects without dependency arrays). Fixes: key the effects on stable ids, pass `combine` to `useQueries`, hold `at`/`undo`/`view` in refs.
- **Wasted request** — `PictureField.tsx:45`: the picker always fetches the first page of videos, used only for audio pickers. Fix: pass `enabled`.
- **One chunk** — `App.tsx:147-165`: every screen is imported statically. Fix: `React.lazy` per route (Setup, the timeline editor with `timeline/*`, Queue with its charts, Workflows, People) and lazy-load the mask painter, Trim and the Designer where they open.
- **Swallowed upload errors** — `TimelineEditor.tsx:834`, `Shelf.tsx:232`, `Studio.tsx:579`: a failed drop or pick does nothing visible. Fix: route through the banners as `TileMenu` does.

### Packages, node pack, release
- **Transitive dependencies resolved fresh at every image and bundle build** — `stage.mjs:66-75`, `Dockerfile:31`: direct versions are pinned, nothing else, no lockfile. Fix: `npm install --package-lock-only` during staging, `npm ci` after.
- **`helm uninstall` deletes the data** — `chart/templates/pvc.yaml`: no `helm.sh/resource-policy: keep`. Fix: add the annotation.
- **Exponential recursion in workflow inspection** — `packages/workflows/src/inspect.ts:102-113`: `usedAs` recurses six deep over every consumer and six slots with no visited set. Fix: carry a `Set` of visited `node:slot` keys.
- **A ComfyUI rename turns every continuation node into a bare ImportError** — `continuation_nodes.py:414-423`: the capability check imports a private module and inspects a constructor. Fix: `try/except ImportError` with the "needs commit e01fb4c or newer" message.
- **The fake ComfyUI's progress differs from the real one** — `testing.ts:278-282` (see HIGH 5).

## Structure

Where splitting makes the code safer, not just shorter.

- **`apps/server/src/app.ts`**: keep `buildApp` as wiring (Fastify setup, parsers, static SPA, error handler, the `register*` calls, about 120 lines) and move the inline routes to `assets-api.ts` (list, search, file, thumb, keep, bin, upload), `jobs-api.ts` (jobs, warm, queue control), `events.ts` (the SSE route with one shared load timer) and `lookup-api.ts` (Civitai, embedded, downloads, resolve, fetch).
- **`apps/server/src/timelines.ts`**: keep `Timelines` as the model (placement, joins state, list, view, undo/redo, clip and take edits, plan/finished) and move the rest to modules taking `{ db, storage, events, placed }`: `timelineRange.ts` (laid/window/split/cut/regenerate/loop/slow), `timelineMedia.ts` (frame/strip/motion/scenes/peek/joins/matches), `timelineExport.ts`.
- **`apps/server/src/queue.ts`**: keep the state machine (start/stop/enqueue/cancel/reorder/pause/pump/run/finish) and split `queueSubmit.ts`, `queueStore.ts` (where the idempotency guard belongs), `queueTools.ts` (cut, export), `queueView.ts` (status, history, preview).
- **`apps/web/src/screens/Setup.tsx`**: ten self-contained cards already; move each to `screens/settings/` and keep the tabs and the search.
- **`apps/web/src/screens/TimelineEditor.tsx`**: `useClipEdits` (which is also where the lost-edit fix lives), `useRange`, `useEditorKeys`, pure menu builders in `timeline/menus.ts`, and `ExportDialog`, `CastDialog`, `Overview`, `StartPanel` as files; the screen becomes layout.
- **`apps/web/src/Viewer.tsx`**: `useViewerActions`, `ViewerMedia` (shared by inline and overlay), `ViewerSidebar`. **`Studio.tsx`**: `CreatePanel`, `DraftResults`, `useLibraryFilters`, `useSelection`. **`People.tsx`**: one editor per entity kind and a shared `useDebouncedSave` with `draft.ts`. **`Track.tsx`**: `TrackClip`, `TrackRuler`, `useTrackDrop`, `useMotionMarks`. **`api.ts`**: the types into `api/types/*.ts`; longer term, exported from the server's zod schemas so a drift is a compile error.
- **`packages/recipes/src/h3/video.ts`**: `resolveJoin`, `frameFor`, `loadH3Model`, `conditionFor`, `latentUpscalePass`, `finish`, with the inputs array in `h3/inputs.ts`. **`packages/workflows/src/inspect.ts`**: one function per `// ----` section it already has.
