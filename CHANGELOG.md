# Changelog

Every release of Afflatus, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/) (0.x: anything may still change between minor versions). The bundles and the image of each version are on the [releases page](https://github.com/bardak971/afflatus/releases).

## [Unreleased]

### Fixed
- **Settings › Model files took one file seen through two folders for two copies, and deleting the "extra" one deleted the only one.** When extra_model_paths.yaml lists the same folder twice (A1111's Stable-diffusion as checkpoints and its sub-folder as diffusion_models), or models/unet is read as diffusion_models, the same file on disk showed in two places with the same sha256: counted twice, called a copy of itself, picked by Select the copies, and let go by Delete as "a copy of it stays". Copies are other files on disk with the same sha256, as before. Empty now lists what it erases, each file with its size, and says which ones are the only copy left, the button saying how much is erased for good. A folder linked into a model folder (a junction) is now walked, as ComfyUI does.
- **A paid Civitai version (Early Access, Buzz) is said as paid, before and after its download.** Find models shows **Paid** or **Early Access · until <day>** on the card, in the version picker and in the command bar's rows, and asks before picking it (Pick anyway); the download stays possible. A refused download says Civitai's own reason with the version's page (it said "save a key in Settings" to a user whose key was saved and valid), and a key Civitai refuses is said as such; a rented GPU says the same instead of "no download link of its own". `find_models` gives `paid` on such versions. The key's place is named as it is now, Settings › Models › Civitai API key.

## [0.8.3] - 2026-10-30

Seamless joins that say when they cut (a reference picture's continuation told its run-up, in positive words), the Face refine and upscale models chosen per clip (one model in memory on Swap), every LoRA a render loads shown in the LoRA list with its weight, Swap's windows all swaps, and no more "ComfyUI is offline" for one late answer.

### Added
- **Face refine model, per clip.** Every H3 form (Video with audio, Lip sync, Swap character, Motion transfer) and Finish choose the model the faces are redrawn with: the fused refdelta turbo, any H3 reference model or hybrid, or **Clip's own model**, which runs the pass on the clip's own loader with its turbo LoRA when Turbo is on (on a fresh pod, the reference turbo LoRA a reference clip was made with), one model in memory (a Swap held its swap model and the turbo at once, and every job reloaded the other). Swap starts on its own model, the other forms on the fused turbo, or on the clip's own where that file is missing; a clip made by the frames model, which follows no picture, takes the fused turbo, and its job says so. Face refine steps follow the model (4 on a fused or distilled turbo or the clip's model with its turbo, 10 on a full model) unless typed. A clip made before keeps the turbo. Clip's own model is offered by Face refine alone: set on another model input through MCP or the API (SeedVR2's, the latent upscaler), it is refused before anything is queued.
- **Every LoRA Afflatus adds by itself is a row of the LoRA list**, first, with its file (the Settings › Models slot's unless another is picked; the slot's kind listed first, any LoRA allowed) and its weight. Turbo's LoRA on H3 (every form), Qwen Image and Qwen Edit, and Wan (a row in each list: the high-noise one weighted by High-noise turbo, the low-noise one by a weight of its own) shows while Turbo puts it on; its × turns Turbo off, and turned on again it comes back with the file and weight chosen before. What a model needs has a row without a ×, at 0 not loaded: LTX's distilled LoRA on a model that is not distilled, SCAIL-2's DPO and step-distill LoRAs, Krea 2's style-reference LoRA with reference images. The same file added by hand is that row: one loader, at the weight typed (Turbo on with its LoRA also in the list was loaded twice, at about 1.8); added by hand at 0, it stays a row of its own and Turbo's row keeps its weight, as before. Face refine on the clip's own model keeps Turbo's LoRA at the row's weight. Left as they start, renders are unchanged. `describe_form` lists the rows.
- **Upscale models, per clip.** H3's latent upscaler file (the re-sampling stays on the clip's own model) and SeedVR2's model (the 3B or the 7B, on every video form) are chosen in the forms and in Finish, as the pixel upscale model was. A model one setting brings in asks a pod for its file only while that setting is on.

### Changed
- **A source made with Swap character gives every window Swap character**, the windows that carry on too. They were made Motion transfer after the first one, a leftover of the retired Swap motion. A window can still be given Motion transfer on its own (its form menu), and then carries on from the swap before it as it did.

### Fixed
- **H3 seamless joins with a reference picture no longer cut to another shot as often.**
  - **The prompt:** a clip that carries on with a reference picture (Video with audio, Lip sync) is now told how long its run-up is and that the rest is the same continuous take, in the same place, light and camera, as the frame-and-words route always was.
  - **Why:** the latent continuation itself held (the run-up is the clip before's own frames), but on 109 H3 joins measured, the model cut to a new shot on the first new frame in 6 of 65 with a reference picture and none of 44 without one.
  - **Positive words only:** both routes now say a continuation in positive words only, since H3 reads a negation as what it names ("Do not … cut, fade, add titles").
- **A seamless join that cut is said on the timeline.**
  - **On the track and the takes:** the circle between two clips turns attention-coloured with what was measured and its figure, and the take's row and the hover card say "cut at the join ×N", with New take beside it.
  - **When:** a hard cut within a second after the run-up (two frames under 17 dB apart, 6 dB more than the frames around them), or the run-up's end jumping past ×3 against the take's own motion. Measured on 173 joins of every family, it found the 11 cuts seen in their frames and nothing else, two of them 10 and 13 frames after the join, where the run-up end figure alone missed them.
  - **Through MCP:** `read_timeline` says it on the join, the take and Needs a look.
  - **Takes already made:** the takes that carry on are looked at once in the background, at the backfill's slow pace.
  - **H3 only:** a cut at the join is said for H3's takes alone, measured at its 24 frames a second where it was tuned; on Wan's 16 it read quick moves as cuts. Other families' run-up end figure shows in Look as before.
- **"ComfyUI is offline" no longer comes for an answer missed.** It was said, on Telegram too, the moment ComfyUI missed one 5-second status poll while it rendered, which a ComfyUI loading a model or on a PC short of memory does and renders on. It is now said once ComfyUI has stayed silent for 30 s in a row while it renders. A render that loses ComfyUI is still said at once.

## [0.8.2] - 2026-10-29

Agents (MCP) that run the whole studio: long calls in the background with MCP Tasks (Claude Code wakes once with the result), the queue, the GPU hunt, uploads, logs and most of what the web can do, every path that spends on a rented pod held to the token's cap; Settings › Model files, every model file on this PC with how Afflatus used it, and Delete to the Recycle Bin to free the space; Access in a tab of its own.

### Added
- **Settings › Model files.** A tab of its own, after Models, with every model file of ComfyUI's folders on this PC (extra_model_paths.yaml's too): its name and picture where Civitai or Hugging Face match its hash, kind, base, size, date, how many Afflatus jobs loaded it and when last, what was made with it, what needs it (presets, model sets, families), its extra copies. On top: the files Afflatus never used since its records start (once it has 90 days of them, those it has not used for 90 days), the extra copies, the files with no match, and the space by last use; they follow a family filter. Sortable columns, search, kind chips, click and shift-click to select. Another machine's files are listed read-only.
  - **Delete** moves to the Windows Recycle Bin, written by Afflatus itself (Explorer lists the file and its Restore works), or to a `.afflatus-set-aside` folder beside the model folders when the bin has no room or erases at once, and on Linux and Docker. Nothing is erased: **Put back**, Undo, and one **Empty** erases them for good. A file a preset or a model set needs is asked about first ("Keep that one, delete 11"), unless a copy of it stays. Never through MCP; the new `model_files` tool only lists.
  - **Drop model files** onto the tab: each goes into its kind's folder, read from its header (or picked on its line).
  - From now on each job keeps the files its graph loaded; renders from before are counted from what was kept of them (helper files approximately, ≈). Renders made straight in ComfyUI are not seen: the words are "not used by Afflatus since…".
  - Settings › Models gets a line on an install with 90 days of records ("X GB not used by Afflatus for 90 days · Model files ›", closable, back after about another 100 GB), and an open family's **its files in Model files ›**.
- **The queue's controls through MCP.** An agent can now put waiting jobs in order (`order_queue`), move one to a machine or back to any (`run_on`), use only one machine (`use_only`), cancel everything waiting (`cancel_waiting`: its own jobs and yours, never another token's) and unload the models (`unload_models`). Moving work onto a rented pod needs Spend and room in the token's spend cap with the moved jobs counted, and a job of yours moved onto a pod becomes the token's: its Queue row names the token and its time there counts against that token's cap. `use_only` onto a pod pins the waiting jobs it counted there and pauses none of your machines, so what you queue afterwards never goes to the pod on nobody's cap. Unloading a pod's models needs Spend and room in the token's cap for the reload, since its next render loads them again on the clock, and is refused on a pod the token did not start while your renders or another token's wait for it.
- **Hunt a GPU through MCP.** `hunt` reads the hunt and ranks the GPUs for the renders waiting; `start_hunt`, `change_hunt` and `cancel_hunt` need Spend. A hunt a token starts must fit its spend cap and the app's caps for a pod at its ceiling, and is checked again when a GPU comes free: a token that spent meanwhile, lost Spend or was revoked deploys nothing, and the hunt ends saying why. The pod it deploys is the token's, counted whole and stopped at its cap. A token changes only a hunt it started, and cancels its own or yours; changing a token's hunt in Afflatus makes it yours.
- **MCP: an agent uploads a file.** `upload` takes a picture, a video or a sound as base64 (a `data:` address too) through the web upload's own path: read from its bytes, the real containers only (a playlist or a manifest naming other files is refused). It goes into a folder or a project, and its id then goes where library items go (a draft's references, a kit item's pictures). One file at a time per token (an import from an address counts), at most 16 MB each and 1 GB a token a day. `/mcp` takes a call that large only once its token is known.
- **MCP: what the web did that an agent could not.**
  - Library: `extract_sound`, `remove_sound`, `mirror`.
  - Places: `delete_folder` (its items move up; a linked folder stays linked), `archive_project`, `delete_project` (what it holds goes to the Inbox), and `look_again` on a linked folder.
  - Prompt kit: `delete_kit_item`.
  - Timelines: `duplicate_timeline`, and `delete_timeline`, which takes the timeline's name back as a check and is refused while a clip of it is in the queue.
  - Workflows: `read_workflow`, `edit_workflow` and `delete_workflow`. A workflow whose mapping an agent changed waits for your Approve again, even one you imported.
  - Storage and tidying: `storage`, `bin_idle_takes` across every timeline, `clear_unused_drafts` (the draft open stays), `dismiss` for a finished job.
  - docs/mcp.md's never-list now also names approving a workflow, installing node packs, deleting network volume files, forgetting render times, backups, sharing an item and linking a folder.
- **Duplicate a timeline.** The timeline's menu (Projects panel, command bar) has **Duplicate**: a copy beside it with its clips, forms and takes (the same videos play in both), its music, source and recordings. Its Undo history, jobs and last export are not copied. The copy opens at once.
- **MCP: what goes wrong, and where to look.** `comfy_log` reads a machine's ComfyUI log (a pod's boot log while its ComfyUI is not up), the last lines or those holding some words. `boot_log` reads a pod's boot now, or the boot logs Settings › Rented GPUs keeps. `job_live` gives a running job's phase, its Preview nodes' pictures and its live preview, as a picture. Secrets never reach the agent from a log: every key and token Afflatus keeps, and anything shaped like one (`token=`, a Bearer, `hf_…`, a password in an address), shows as `[hidden]`; a folder on the disk shows as its file's name. `render_stats` (the Render times tab), `network_volumes` and `model_updates` (hashes and newer versions) are read-only.
- **MCP: a model's page and trigger words, and prompts.** `model_page` gives what a file's header says (its trigger words and training tags), its page, and the words that call it up, and looks them up on Civitai and Hugging Face when asked. `set_model_words` (Manage) sets your own words for a file. `prompt_history` lists the prompts rendered before, `check_tags` runs the Danbooru tag check, and `prompt_from_parts` gives the prompt a form writes from its parts.
- **MCP: `show_page` opens what an agent made on your screen.** It can open a draft, a timeline with one of its clips selected, a library item in its folder, or a Settings row. The page in front goes there, unless you typed in the last 5 seconds: then a toast says "<token> wants to show you …" with **Go**, and nothing moves. The agent is told which happened, or that no page of Afflatus is open or in front.
- **MCP Tasks: long calls followed by the client, not the agent.** A client that takes MCP Tasks (protocol 2026-07-28) gets a task from `render`, `render_clips`, `finish`, `export`, `run_workflow`, a slow motion of `cut_range` and `deploy_pod`, follows it on its own, and hands the agent the result once the work has ended: the call's answer with each job's end as `job` says it (what it made, or why it failed), or whether the pod's ComfyUI answers. Nothing is sent while it runs, and the agent spends nothing on the wait. Cancelling the task cancels its jobs as `cancel` does; a pod's task only stops being followed, the pod stays up. The call is the same call (scopes, limits, spend caps, activity); a task is its token's alone, survives a restart, and is forgotten after a day. A client without Tasks gets the answer as before.
- **Long calls in the background with Claude Code.** Settings › Access has the line of `~/.claude/settings.json` that makes Claude Code follow MCP Tasks when it runs through the Agent SDK (Sillage, scripts): `"env": { "CLAUDE_AUTO_BACKGROUND_TASKS": "1" }`, with a Copy. A long render then goes to the background, the session stays free, and it is woken once with the result; without the line, the render holds the session. Each token's row now names its client with its version, says "follows Tasks" or "Tasks off" from its last call, and links a Claude Code without Tasks to that line. `job`'s `wait` stays, for the clients that do not follow Tasks. docs/mcp.md › Long calls says the same.

### Changed
- **MCP on the v2 SDK.** `/mcp` now speaks protocol 2026-07-28 (each request carrying its own envelope) beside the 2025 handshake, still stateless with JSON answers. Dependencies: `@modelcontextprotocol/server` and `@modelcontextprotocol/core` 2.4.0 replace `@modelcontextprotocol/sdk` 1.32.2 (Apache-2.0, was MIT); `@modelcontextprotocol/client` 2.4.0 and `@modelcontextprotocol/ext-tasks` 0.2.2 for the tests only.
- **Access has its own tab in Settings.** The password, the devices signed in, the metrics token and Agents (MCP) moved from Interface to **Settings › Access**, after Interface, which keeps the look and the notifications. Old links and Find a setting land on the new tab, and every message and doc now says Settings › Access.
- **MCP's `job` says when to check again** on a job not done: "about 2 min 10 s left: check again in ~130 s", from the queue's forecast. An agent that can wait then checks once instead of polling.

### Removed
- **Claude Desktop's setup.** Settings › Access › Agents (MCP) no longer offers "For Claude Desktop" (its `mcp-remote` block), and the docs no longer describe it. Claude Code and any Streamable HTTP client are set up as before.

### Fixed
- **An agent could send your work onto a rented pod with no cap counting it.** With Spend, an MCP token could pause one of your machines, resume a pod or the whole queue, change what a machine takes, remove one of your machines, or start a GPU hunt that rests your machines, while a pod was up: your waiting work, and everything you queued after, went to that pod, billed to you (or to the token that started it) and counted against no cap. These are now refused while a pod of yours or another token's would take the work; onto a pod the token started itself (its whole run counted against its cap) they work as before. The agent sends its own jobs to a pod with `run_on` or `use_only`, counted.
- Settings › Models: a family row with Get the minimum beside it (Image tools) could show no name in a narrow card.
- **MCP's `job`, `queue_status` and `overview` said the time left in seconds as `leftMs`**, so an agent read 130 s as 0.13 s.
- **A helper model slot could take the wrong file.** H3's RT-DETR slot (and SDPose, SAM 3, SeedVR2) picked a file of its folder by its weights, and could land on a video model kept there; these slots now take only a file their name says.
- **A Civitai address in Download a model from a URL, or a pod's file from Civitai, was fetched without your Civitai key**, and Civitai answered 401 for most files. The key now goes with it, to Civitai alone (never to the storage it redirects to), as the Hugging Face token goes to Hugging Face.

## [0.8.1] - 2026-10-28

The first hour made plainer (a ComfyUI too old said with what to do, each family's minimum with its size, Create open on a first landing, a timeline clip waiting for its files), H3's latent finish with its real noise level, SeedVR2 7B restoring 49 frames together, and rented pods: model lists that say where each file is, a stopped pod's Start, Deploy on its volume when RunPod refuses it, and cap refusals that say their sum.

### Added
- **Afflatus says what your ComfyUI is too old for, and what to do.** When it connects to a ComfyUI it reads its version and PyTorch from `/system_stats` (both shown as chips in Settings › ComfyUI, on each machine's card and on the first launch). A ComfyUI too old for some families gets a "Too old for" row naming them (or the forms of a family it runs only in part) and the version they need, read from ComfyUI's own releases: MiniMax H3 needs 0.30 (0.35 for Motion transfer), LTX 2.3 0.8, LTX 2.5 0.32, Qwen Image 2.1 0.37, FLUX.2 Klein 0.3.72, SeedVR2 0.28. It says to update ComfyUI, with **Copy what to run** when its folder is on this PC (the portable's `update_comfyui.bat`, or `git pull` and its requirements with its own venv's Python). A PyTorch built for a CUDA older than 13 gets a row too: ComfyUI then runs the int8 (convrot) and NVFP4 files without its CUDA kernels, slower. A form whose missing nodes are ComfyUI's own now says "update ComfyUI" with the version that brought them, never ComfyUI-Manager's "Install Missing Custom Nodes", which cannot find them; a custom pack's nodes keep the Manager advice. MCP's `list_machines` says the PyTorch and what the version is too old for.
- **Restart ComfyUI on the node pack's row.** Once the node pack is written and not yet loaded, Settings › ComfyUI offers Restart ComfyUI (through ComfyUI-Manager, as its own Restart does, refused while a render runs), then says the pack loaded. Without ComfyUI-Manager the row says to restart ComfyUI the way you started it.
- **Model lists across machines say where each file is**. With a rented pod in the settings, the Model and LoRA lists count your ComfyUI's files apart from those only a pod has, list a pod's own under its name, and say which machines have a file that is not on all of them; a pod's file is grouped by what it is for, its header read on the pod. A stopped pod's network volume (as last listed) and the files of the Model set it was deployed with are offered greyed, as official files are (`list_models` with a folder says them too). A render that picks one, with no machine able to run it now, waits for that pod: its Queue row says "waits for pod <name>" with a **Start** that asks first with the pod's rate, as the Rented GPUs page does, greyed and refused past a spending cap; it is never sent to your ComfyUI. With no pod left, a render asking for a file none of your ComfyUIs lists and that has no known download is refused as it is queued, rather than failing at its build.

### Changed
- **A first landing on Studio shows Create open**, on a family whose files are all here, and it stays open until you fold it once (remembered in this browser; a browser that used Studio before keeps folding as it did). Folded, the whole "CREATE ＋" strip opens it, and the empty library says Create is on the left, the word itself a way to open it. A timeline clip whose model lacks only files with an official download now renders as Studio's form does: queued, its Queue row waiting for the files, rather than Render greyed with "A model file it needs was not found" (a missing node or a file with no known download is still refused). The first-run page says where Deploy a GPU… really is (the status bar, Settings › Rented GPUs, the command bar), not the Queue.
- **Settings › Models says what to get first.** A family whose files are not here says what its first operation needs ("Video with audio needs 4 files" and their size), with **Get the minimum** beside it, the same count, and a quiet **Everything** when its other operations need more: H3's minimum never fetches Swap's reference model and LoRA, and LTX 2.3's is its one checkpoint and text encoder, its split files listed as the other way to have it. Sizes come with every count (a "+" while some are not known yet); opened, a family marks its minimum files and says what an optional one is for. When nothing can download into the ComfyUI (no folder Afflatus can write, no node pack, no ComfyUI-Manager), one line at the top says so with **Set the folder** and **Or a pod fetches them**, and the Download buttons show as off rather than as links. Failed downloads into your ComfyUI make one banner, their shared reason said once, not one sticky banner per file; Settings › Downloads says what goes wrong with a file while it tries again. The form's model picker says why a family is not ready: its files missing with their size, or the nodes ComfyUI lacks.
- **The recording lane opens its stage where it is clicked.** A click anywhere on a recording's band on the Audio row opens it on the stage at that moment (only its name did, and at the track's start); a drag still slips it, and its name stays in view at the track's left while a long timeline is scrolled. The stage's playhead starts at the moment clicked, or at the timeline's playhead when opened from the keyboard, and the track, whose stretch the stage shows, is centred on it, so the stage's view and playhead agree. A clip is opened from the Video row; a right-click on the band gives the menu of the clip's audio under it, and a drag from the library goes through to the clips' Audio cells.
- **The timeline's zoom and scroll are kept per timeline** in this browser and brought back on return; a timeline left fitted (Fit all) is fitted again, and one that changed length since is shown within its new end.
- **An MCP spend-cap refusal says the sum it was asked**, not only what was spent: the token's cap, its spend this month, what is committed (its jobs running and waiting, the pods it runs and their next hour) and what the call adds (a render's jobs, a pod's first hour), with the total. The app's own caps say the same with the pods up by name and price, and a job held as `CAP_FULL` says its figures on its Queue row.
- **H3's latent re-sample: its denoise is the real noise level**. The Finish dialog's and the H3 forms' re-sample denoise is now the σ the re-sample starts at, whatever the model's shift, eased down to 0.012 on a karras curve (ρ 7), then 0, over its steps. Before, it was BasicScheduler's denoise at the clip's shift: 0.15 over 2 steps at shift 8 really re-noised to σ 0.59, then jumped 0.40 → 0, and redrew mouths. The default is now 0.35 in 3 steps: 13 to 20 % less flicker on moving edges than before, the draft's likeness and mouth shapes kept better, for about one more step of time; lower starts flicker less still but leave the upscaler's grain and smooth skin on close-ups. **Values saved before** (drafts, values per model, takes finished again, jobs in the queue, the Finish settings): the old default pair, 0.15 with 2 steps, reads as the new default; any other value reads as the σ it really started at, its steps kept. That is worked out at the clip's own video shift, or at shift 11 for the Finish settings, which know no clip. So a finish you had tuned keeps its strength and only gets the gentler end. A finish made before is never the same as one asked now: Redo › Changed finishes it again. In the MCP `finish` tool, `latentDenoise` is now `latentNoise`.
- **The SeedVR2 upscale encodes and decodes with ComfyUI's plain VAE nodes** instead of its template's 512 px tiles with 128 px of overlap, which worked through the frame about 1.7 times over. ComfyUI's SeedVR2 VAE then sizes the work itself from the card's free memory: the whole frame when it fits, else the largest tiles that do. A 124-frame clip doubled to 2048 × 1152 went from about 13.5 to 8 minutes on an A40, with the 7B as with the 3B, keeping its frames and colour and leaving no tile lines; nearly all of what is left is the VAE itself, the model taking under 30 s.
- **SeedVR2 7B restores 49 frames together**, with 2 latent frames crossfaded between passes: a 124-frame clip in 3 passes rather than 25 of 5 frames, no bump where passes meet, cleaner from frame to frame, in the same time on an A40. A card that cannot hold 49 frames at the size asked gets the widest window it holds (4n + 1, worked out by ComfyUI's own memory law on the card's memory), never under 5. The 3B keeps its window by the frame's size. The form's "SeedVR2 frames together" and the Finish dialog's batch size still take a number, 0 being this default.

### Fixed
- **A render pinned to a stopped pod offers Start.** Its Queue row says "waits for pod <name>" with **Start** (the rate and idle stop asked first, refused past a spending cap) whatever else is up, and it never goes to another machine unless you move it; it said "the pod is stopped" with no Start whenever your ComfyUI or another pod could have run it. Render on can now pick a stopped pod ("stopped · waits for it"). A stopped pod's volume or set file picked in a form says only that the job waits for that pod, no longer "ComfyUI does not have it" under it. A pod's card shows its idle and watchdog minutes when they are not in the list (3 min read "Choose…"), and a pod on a network volume says the volume's size and what its models hold rather than RunPod's whole shared storage ("1663254.3/2190892.5 GB").
- **A Start RunPod refuses offers Deploy on its volume.** When RunPod has no GPU free on a stopped pod's host (which it said at every Start of a real-pod check), Afflatus asks whether to deploy a new pod on the same network volume, its models already there: the same GPU, or when none is free there the cheapest one with as much memory, said plainly; the rate, the idle stop and, with no volume, that its models are fetched again, in the question. It goes through the usual deploy and its spending caps, and the renders pinned to the stopped pod move to the new one; the stopped pod stays as it is.
- **A render pinned to a pod that went stays pinned.** After its pod's idle terminate or a Terminate, it waits with "its pod was terminated" and Deploy a GPU… on its Queue row, until you move it (Run on); before, it fell to your own ComfyUI and failed at its build. Queuing one pinned to a pod already gone is refused with why.
- **A Model set's file is fetched by any pod.** Its download address was known only to the deploys of that set; another pod that needed it failed with "no site is known".
- **A pod's idle stop goes down to 1 min** in Deploy and on its card (the lists started at 5).

## [0.8.0] - 2026-10-28

Afflatus from outside: an MCP server that lets Claude Code, Claude Desktop or any MCP client drive the whole studio with a token of its own (every form and setting, renders it can look at, timelines, the library, the Prompt kit, models, machines and rented GPUs), held to its scopes, its renders an hour and its spend cap, its changes shown live in the page you have open with Undo.

### Added
- **Afflatus from outside: an MCP server**. - **Stop during a render's uploads** stops it: no more uploads, no freeing of ComfyUI's memory and no prompt sent after it; ComfyUI is asked to interrupt only a prompt that is running.
- **Media fields** (picture, clip video, references, sound) all show a file being added and say why one was refused; a file of the wrong kind is refused in words.
- **Clip form edits** are kept when the page is reloaded at once, saved one at a time, and the browser asks before closing while a save has failed; Mirror on a pin just changed keeps its flip.
- A right-click menu left open no longer takes the keys of Ctrl+K opened over it.
- The timeline editor's header keeps every button reachable down to 800 px (Finish and Export become icons), and Settings' search stays reachable on a narrow window; the status bar fits at 500 px.
- Splitting a clip finished by SeedVR2, RTX or an upscale model no longer marks its second half "Mirror changed" (Render missing would have rendered it again).
- Removing a take whose video lies in a linked folder leaves the file in that folder instead of binning it (emptying the bin would have erased it from the disk).
- A library search with a control character in it no longer fails; a page on another port of the same machine can no longer make Afflatus build a backup; a live preview is only served as a picture or video.
- Load works on a form that has not got its pictures yet; Ctrl+Enter in Ctrl+K no longer starts a render; a dismissed download failure stays dismissed after a reload.
- Importing a preset file that is not one says so plainly; Copy link and copying a snippet say they did.
- Every picture slot has its "?": the Keyframe, and the tool forms' Image and Mask.
- Compare: the wipe fits the stage.

## [0.3.0] - 2026-10-10

### Added
- **Seamless MiniMax H3 chains.** A continuation starts from the clip before's own latent, and the whole chain is decoded as one piece at the joins, so a join plays as a plain cut. Grid-length joins, latent cuts, fades and a smooth hand-over in the player. Needs node pack 0.10.0.
- **Finish from the draft's latent** for H3: a re-sample that keeps the motion and the seamless joins, beside SeedVR2, RTX Video Super Resolution and upscale models. Upscale metrics per finish.
- **Music ducking** under speech, with a depth in dB, heard the same in the player and in the export.
- **Built-in passes** found across real workflows: detail boost (Detail Daemon), tiled redraw, SageAttention and torch compile, ControlNet guide (pose, depth), Redux look.
- **Workflow importer** built from a corpus of 233 real workflows: forms start with what the workflow's author put forward, a suggester for the rest, missing node packs installed through ComfyUI-Manager with ComfyUI restarted from the card. Every imported graph is checked against ComfyUI's own API export.
- **Projects:** a tree in the rail, Name · Created · Size columns, unused takes, Move to another project from the folder menu. Everything made in a timeline lands in its folder.
- Renders get a name when they are made.
- **The command bar (Ctrl+K):** everything across projects (drafts, renders, timelines, folders, people, settings) with a preview, and commands from the keyboard: go to any screen, queue, cancel and reorder jobs, reuse a render with or without its seed, split a clip, flip a setting, bring back an earlier prompt, empty the bin or put it all back, and a calculator for frames, seconds and sizes on the model's own grid (`=`). Prefixes narrow it: `>` commands, `#` places, `/` settings, `!` queue, `"` prompt history, `?` keys.
- Projects in the rail (pinned ones as buttons, moved with Alt+arrows) and folders in a breadcrumb; the Bin as a place of its own.
- **Mirror** a picture (horizontally or vertically), from the viewer or the right-click menu: a new kept copy beside it.
- **For the web** on export: a copy at most 10 or 25 MB, 1280 px on the long side, 30 frames a second.
- The Designer as a side panel, in Studio and for each clip of a timeline.
- Keyboard: a searchable sheet of every shortcut; S or Ctrl+B splits a clip at the playhead; L / Shift+L reuse a render with the same or a new seed.
- Queue: the running job's live speed, elapsed time and seed; waiting jobs grouped by model, with the model each one loads.
- Settings → Appearance: play videos and sound on hover (per browser).
- The timeline player is checked frame by frame in headless Chrome in CI, and the export in the tests.

### Changed
- The presets that ship are on the official model releases (Krea 2 Turbo, MiniMax H3, Wan 2.2 image to video, LTX 2.3 distilled), fetched from the publishers' Hugging Face pages. Community fine-tunes are shared as preset files instead (Save as a file, Import); `presets/README.md` says how.
- Krea 2 runs on the shared flow recipes, like the other picture families.
- **Studio Dark with the coral accent** is the default theme; the light themes were redone so they read.
- One list of actions per kind of media, the same in the grid, the viewer and the command bar; menus stay inside the window.
- Clicks change the screen at once (keep, rename, move, bin, put back) and overlays open and close without waiting.
- **A blank draft is no longer saved:** a new form is written once it holds something (a prompt, a picture, a name, someone from the kit, a render). No more "No prompt yet" drafts in the lists.
- Faster at scale: the library and the Queue's history hold up at thousands of items, and the first load is lighter.
- A missing node pack is named on the form and in the queue, with how to install it.
- A clip added brings the whole timeline into view; the zoom goes down to 2 px a second for long videos.

### Fixed
- Timeline splits, landings and undo; videos are cut from their files.
- Queue, migrations, bin and backup fixes from a full code review.
- The web app: error boundaries, fewer refetches, contrast, drafts and the Create form.
- A hand-trimmed clip that carries on from the one before lands on the model's own frame grid, so the join stays seamless.
- A failed render says where it failed; a render lost in a restart is not rendered twice; Undo after a take lands in order.
- Linked folders never lose a row to a bad read, a rename or a split.
- The workflow importer reads the output's real frame rate, start and end pictures by their wiring, and duplicate node ids.
- Typed values in steps of 0.01 (denoise) are no longer rounded to the slider's step.

### Security
- Cross-site and unmarked writes are refused (every write needs a JSON body, a file upload or the `X-Afflatus` header).
- Uploads are marked, linked folders and outbound fetches hardened, hostile workflow files refused.
- A stored LLM key stays on the server; frame and cross-site read protection; PNG text and ffmpeg inputs are bounded.
